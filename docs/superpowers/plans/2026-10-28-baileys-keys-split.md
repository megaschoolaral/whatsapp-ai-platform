# Baileys кілттерін жеке жолдарға бөлу — жоспар (кейінге қалдырылған)

Күйі: **бастамаған**. 29.10.2026 шот кезеңі жабылғаннан кейін Railway шотын қарап, содан кейін шешеміз.

## Мәселе
`WhatsappSession.encryptedKeys` — бір үлкен шифрланған блоб. `backend/src/services/whatsapp/sessionStore.ts` оны өзгерген сайын әр 30 секунд сайын **толық** қайта жазады (`KEYS_FLUSH_MS`).

Өлшем (2026-10-28, шифрланбаған JSON):

| Тенант | Блоб |
|---|---|
| Массаж Жумазия | 4.5 MB (sender-key 1.5, pre-key 1.2, session 1.2) |
| врач травматолог | 3.3 MB (disconnected) |
| time travel | 1.3 MB (disconnected) |
| Хостел 777 | 0.8 MB |
| хостел | 0.4 MB |

Қосулы 3 тенант ≈ 5.8 MB × әр 30 с ≈ ~500 GB/ай. Бұрынғы шот (653 GB егресс) public DB URL арқылы осыдан болған. URL ішкіге ауыстырылды (DATABASE_URL = `${{Postgres.DATABASE_URL}}`), егресс ~0.

## Дизайн
1. Жаңа кесте `WhatsappAuthKey (tenantId, type, keyId, encryptedValue, updatedAt)`, PK `(tenantId, type, keyId)`, әр мән AES-GCM-мен шифрланады, `onDelete: Cascade`.
2. `sessionStore.ts`: жадтағы `keysData` қалады (`get` жылдам). `set` өзгерген `(type,id)` және жойылған кілттерді бөлек жинайды. Әр 30 с тек өзгерген жолдар жазылады (`INSERT … ON CONFLICT DO UPDATE` + `DELETE`, бір пакет).
3. Қосылғанда: жолдар бар болса — солардан оқу. Жоқ болса — ескі `encryptedKeys` блобын бір транзакцияда жолдарға көшіру.
4. `connect.ts` ішіндегі сессияны тазалау жаңа кестедегі жолдарды да өшіреді.

## Қауіпсіздік
- `encryptedKeys` бағанын 1 апта сақтау (кейін өшіру). Кері қайтарсақ, блоб ескірген болады, жаңа кілттер жоғалуы мүмкін — тәуекел ескеріледі.
- Алдымен `RAILWAY_DEPLOYMENT_OVERLAP_SECONDS=0`: деплой кезінде ескі және жаңа инстанс бір тенантқа бір мезгілде жазбасын.
- Деплойды төмен жүктемеде жасау, көшіруді қосулы тенанттар үшін автоматты жасау.

## Қадамдар (TDD, бөлек коммиттер)
1. Prisma миграция және `WhatsappAuthKey` моделі.
2. Диф-трекинг және пакеттік жазу (vitest, mock Prisma): жаңа/өзгерген/жойылған кілттер.
3. Блобтан жолдарға көшіру (тест: нәтиже бастапқымен бірдей).
4. Қайта қосу және тазалау сценарийлері.
5. Локалда тексеру: тест тенантпен қосылу, хабарлама алу/жіберу.
6. Рұқсатпен деплой, содан кейін лог пен Network графигін бақылау.

## Пайдасы мен шектеуі
- Береді: DB жазуы ~1000 есе азаяды, CPU (4.5 MB JSON + шифрлау әр 30 с) және Postgres TOAST ісінуі кетеді.
- Бермейді: Memory (~$22.7). Кілттер жадта қалады (~5 MB), жадтың негізгі бөлігі Node, Baileys және сессиялардың өзі.
- Егресс ішкі желі арқылы қазірдің өзінде тегін, сондықтан ақшалай үнем аз.

## Шешім өлшемі (29.10-дан кейін)
Railway Usage-те егресс шынымен түскенін растап, содан кейін осы жұмыстың қажеттілігін шешу.
